# M159 code health follow-ups

Tasks found by reviewing upstream changes in `158.0.8127.2..159.0.8140.3` (6048
commits) for regressions, deprecations and code-health migrations that apply to
Brave. Tick items off as they land.

## 1. Regressions

### History and Page Embeddings services are never built

[776b53ff6a48](https://chromium.googlesource.com/chromium/src/+/776b53ff6a4877127011f59a576786063d3935df)
drops the `IsHistoryEmbeddingsFeatureEnabled()` gate from
`PassageEmbedderModelObserverFactory::BuildServiceInstanceForBrowserContext()`,
which now returns `nullptr` unless `kPassageEmbedder` or `kPermissionsAIv4` is
on. Brave disables both, and its `#define IsHistoryEmbeddingsFeatureEnabled()`
in the factory's shadow now matches nothing, so the observer is never built.
`HistoryEmbeddingsServiceFactory` and `PageEmbeddingsServiceFactory` refuse to
build without it, so `BraveHistoryEmbeddingsService` is gone even with the
Semantic history search toggle on: Leo's history search and tab search lose it
silently. Verified statically.

- [ ] `chromium_src/chrome/browser/passage_embeddings/passage_embedder_model_observer_factory.cc`:
      gate the factory on `BraveHistoryEmbeddingsEnabledAtStartup(profile)`
      instead of upstream's feature check (e.g. a plaster on
      `BuildServiceInstanceForBrowserContext`), and drop the dead `#define`
- [ ] `browser/history_embeddings/README.md:49-57`: describe the new gate
- [ ] Add a browser test: `HistoryEmbeddingsServiceFactory::GetForProfile()` is
      non-null with the toggle on at startup, and null with it off

### Brave's `OnChanged()` no longer runs at the end of `LocationBarView::Update()`

[7be8038030d4](https://chromium.googlesource.com/chromium/src/+/7be8038030d478d257e4f7ed25cf1e2b89805f7a)
adds `kOmniboxSkipRedundantLocationBarUpdates` (enabled). With it,
`LocationBarView::Update()` sets `in_update_`, which makes the virtual
`OnChanged()` return early, and ends with the new non-virtual `OnChangedImpl()`.
`BraveLocationBarView::OnChanged()`
(`browser/ui/views/location_bar/brave_location_bar_view.cc:208`) sets the Brave
actions' hide state and the search promotion button, so both go stale after tab
switches and navigations. Upstream moved its own page-action hiding into
`Update()`.

- [ ] `brave_location_bar_view.cc`: run Brave's half of `OnChanged()` after
      `LocationBarView::Update()` too (or `make_virtual` `OnChangedImpl`), or
      pin the feature off with an `app/feature_defaults_unittest.cc` entry
- [ ] Browser test: switching tabs updates Brave actions and the search
      promotion button

### Request-OTR and debounce host lookup keeps a trailing dot

extensions/common/url_pattern.cc") strip one trailing dot. Upstream strips all
of them since
[b2d2df8dfd69](https://chromium.googlesource.com/chromium/src/+/b2d2df8dfd694f0b45ca00a6f493da35ca8831d6)

[174d64d0fda3](https://chromium.googlesource.com/chromium/src/+/174d64d0fda37f62aba7ba0986cbb0677c87a398)

caches, so neither Request-OTR nor debounce rules run for it.

- [ ] `components/request_otr/browser/request_otr_rule.cc:31`: use
      `base::TrimString(host, ".", base::TRIM_TRAILING)`, with a unit test for
      `example.com..`
